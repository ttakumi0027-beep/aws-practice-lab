## 構築手順

### 1. ホストゾーンの設定

- ドメインの取得（お名前.com）
- ホストゾーンにドメインを登録
- お名前.comに、NSレコードを登録
- EC2インスタンスのパブリックIPアドレスをAレコードに登録
- ドメインの確認

```bash
# IPアドレスが返ってくること
nslookup <ドメイン名>
```

### 2. シンプルルーティングの検証

- インスタンスのAMIを作成
- AMIをシンガポールとシドニーにコピー
- Aレコードに複数IPを登録
- 各サーバのindex.htmlの修正
- 下記のようにDNS応答で複数のIPアドレスが返ることを確認
<img src="../images/tokyo.png" width="400">
<img src="../images/singapore.png" width="400">
<img src="../images/sydney.png" width="400">

### 3. 様々なルーティングの検証

#### シンプルルーティング

- Aレコードに東京リージョンのALBエイリアスを設定
- Tokyoが表示されること

#### 加重ルーティング

- 加重度を"東京: 50/シンガポール: 25/シドニー: 25"に設定する
- 東京、シンガポール、シドニーの画面が表示されること

#### レイテンシールーティング

- 東京、シンガポール、シドニーのレイテンシーAレコードの作成
- 東京が表示されること

#### 位置情報ルーティング

- 場所を"東京: アジア/シンガポール: 欧州/シドニー: オセアニア"に設定する（検証目的）
- 日本に住んでいるため、東京が表示されること

#### 複数値回答ルーティング

- ヘルスチェックをIPアドレスごとに作成
- 下記のようにヘルスチェックが正常であることを確認
<img src="../images/health_check.png" width="400">

- 東京、シンガポール、シドニーに複数回答ルーティングの設定
- 東京、シンガポール、シドニーが表示されること

#### フェイルオーバールーティング

- Primary：東京、Secondary：シンガポール、シドニーに設定
- 東京が表示されること

### 4.フェイルオーバ-構成の構築

- RDS（Test-rds01）の作成
- NATゲートウェイの作成
- RDSリードレプリカをシンガポールへ作成
- シンガポールリージョンにサーバ構築
- フェイルオーバーの定義（東京: プライマリ、シンガポール: セカンダリ）

#### フェイルオーバーの検証

- 東京リージョンのApacheを停止

```bash
systemctl stop httpd

# httpdがinactiveになっていること
systemctl status httpd
```

- シンガポールリージョンのブラウザが表示されること

## 学んだこと

- DNSサーバはネームサーバとリゾルバで構成されている
- ネームサーバはドメイン名とIPアドレスの対応を管理するサーバ
- リゾルバはドメイン名を問い合わせると対応するネームサーバへ問い合わせを行い、IPアドレスを取得する
